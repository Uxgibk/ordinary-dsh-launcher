# 安全与凭据

本页是完整的凭据说明与残留风险清单；README 里的《安全摘要》只是它的前 5 条要点。

---

## 安全说明（重要）

### token 是什么

`dsh web` 每次启动都会生成一个进程级 token，形如：

```
http://127.0.0.1:3080/?token=R0bYe9ar6MQcIvuqLoLCELkoM
```

**这个地址等同于登录凭据。** 谁拿到它，谁就能访问你本机的 GUI，进而驱动 agent 执行命令。
它只在本机 loopback 上监听，但端口可以被动转发，地址本身也可以被截图、粘贴、提交。

### 启动器怎么处理它

| 措施 | 说明 |
|---|---|
| 默认全部脱敏 | 主菜单、启动结果、运行状态里一律显示 `?token=••••••••` |
| 收敛到 `[8]` | 完整地址只在 `[8]` 里显示，且需要你主动进入并选择操作 |
| 不做自动复制 | 不再自动写剪贴板；复制必须由你在 `[8]` 里显式选择 |
| 日志清洗 | 启动新实例前、以及停止 GUI 之后，自动把日志里的 token 替换为 `REDACTED` |
| 状态文件保护 | `.dsh-launcher\` 自动生成 `.gitignore`，避免状态与日志被误提交 |
| 自检会检查 | 自检第 10 项会扫出仍含明文 token 的日志并提示清理 |

### 仍有残留风险（请知悉）

1. **运行中的实例，它的日志洗不掉。** dsh 进程持续持有自己的 stdout 文件句柄，
   实测写入会被拒绝（`IOException`）。所以那次日志里的 token 要等 **GUI 停止后**才会被清洗。
   如果你在意，启动完确认能用之后，可以用 `[5]` → `[4]` 停掉再重启。
2. **`state.json` 里保存着完整地址。** 这是 `[8]` 的数据来源，属于功能前提。
   它留在 `.dsh-launcher\` 内，已加 `.gitignore`；请不要把该目录整体复制或提交到别处。
3. **截图与录屏是你的责任。** 启动器无法阻止你把 `[8]` 的界面截下来发出去。
4. **剪贴板是全局共享的。** 在 `[8]` 里复制之后，其他程序可能读到你剪贴板里的地址。
5. **`[5]` → `[2]` 会从网络下载并执行代码**（官方 npm 包）。请确认网络环境可信。
6. **日志里可能有第三方输出。** `web-*.out.log` 是 `dsh web` 的 stdout 重定向文件，
   拿到这个句柄的子进程写什么都会落进去（详见[常见问题](faq.md#常见问题)）。这类内容不经启动器处理，
   清理前请自行判断。

### 建议

- **每次重启 GUI 都会换新 token**，旧地址随即失效。怀疑泄露时重启即可。
- 不要把 `[8]` 里的地址贴进聊天、issue、日志或代码仓库。
- 如果曾经截图或分享过，重开一次 GUI 换掉 token 最省事。
- **把启动器分享给别人之前，先删掉 `.dsh-launcher\`。**
