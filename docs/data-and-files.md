# 文件、可移植性与数据目录

本页收录：启动器需要哪些文件、能否整体搬走 / 改名 / 分享，以及 `.dsh-launcher\` 数据目录里每个文件的用途。

---

## 文件与可移植性（重要）

### 启动器的必要文件

```
ordinary-dsh-launcher\                ← 整个文件夹可以整体拷走
├─ ordinary-dsh-launcher.cmd          双击入口（必需）
├─ ordinary-dsh-launcher.ps1          全部逻辑（必需）
├─ README.md                          本说明（可选）
└─ .dsh-launcher\                     运行时自动生成的数据目录（非必需，可删）
   ├─ .gitignore                      自动生成，防止凭据被误提交
   ├─ state.json                      当前 GUI 状态（含访问地址，供 [9] 使用）
   └─ logs\                           每次启动的 stdout / stderr 日志
      ├─ web-<时间戳>.out.log         dsh web 的 stdout（[6]→[5] 看的就是它）
      └─ web-<时间戳>.err.log         dsh web 的 stderr（通常 0 字节）
```

| 文件 | 是否必需 | 缺了会怎样 |
|---|---|---|
| `ordinary-dsh-launcher.cmd` | ✅ 必需 | 没有它就只能用 PowerShell 手动跑 `.ps1`，不能双击启动 |
| `ordinary-dsh-launcher.ps1` | ✅ 必需 | `.cmd` 会报 `No .ps1 script found next to this launcher` 并退出 |
| `.dsh-launcher\` | ❌ 自动生成 | 下次运行自动重建；只是会丢掉「运行中 GUI 的 PID/地址」和历史日志 |
| `README.md` | ❌ 可选 | 纯文档，删掉不影响运行 |

要点：

- 两个必需文件**必须放在同一个文件夹里**，只复制其中一个不行。
- `.dsh-launcher\` 里含 **token 与项目路径**。分享给别人之前，请先把它删掉。
- `.dsh-launcher\` 内自带 `.gitignore`（内容为 `*`），因此即使整个文件夹进了 git 仓库，状态与日志也不会被提交。
- `.dsh-launcher\` 会**自己长文件**：第一次运行就出现，之后每启动一次 GUI 就多一对日志。
  它到底是什么、每个文件什么用途、哪些能删，见[运行时数据目录](#运行时数据目录-dsh-launcher)。

### 可以随处移动吗？—— 可以

把整个 `ordinary-dsh-launcher\` 文件夹剪切到任何位置都能正常工作，包括含**空格**、**中文**的路径：

- `.cmd` 用 `%~dp0`、`.ps1` 用 `$PSScriptRoot` 解析自身位置，脚本里**没有任何硬编码的绝对路径**；
- 数据目录、日志目录、默认工作目录全部相对于启动器自身；
- dsh 本体装在别处（全局 npm 目录或 npx 缓存），与启动器放在哪无关。

移动后需要知道的几件事：

| 事项 | 说明 |
|---|---|
| **默认工作目录会跟着变** | 默认 workspace 就是「启动器自己所在的文件夹」。想固定指向某个项目，用 `[3]` 自定义参数启动，或改 `$Script:DefaultWorkspace` |
| 同盘移动 | `.dsh-launcher\` 跟着一起搬，历史状态与日志保留 |
| 跨盘 / 拷到 U 盘 | 同上，数据目录一起复制即可 |
| 目标目录必须**可写** | 启动器要创建 `.dsh-launcher\` 与日志；只读目录、部分网络盘会失败 |
| 不要放进受限目录 | 被沙箱 / 杀软拦截的目录可能导致 dsh 写 `DSH_HOME` 失败（症状：`EPERM ... profiles`） |

### 可以任意重命名吗？—— 可以，但有两条边界

- `.cmd` 查找脚本的顺序是：**同名的 `.ps1`** → **同目录下唯一的 `.ps1`**。
  所以两个文件都能改名，也可以改成中文名（如 `启动器.cmd` / `启动器.ps1`）。
- **边界 1：同目录下不要放第二个无关的 `.ps1`。** 一旦出现多个 `.ps1`，「唯一的 `.ps1`」这条兜底就失效，可能挑错文件。
- **边界 2：扩展名不能改。** `.cmd` 必须保持 `.cmd`（双击才会交给命令解释器），`.ps1` 必须保持 `.ps1`（PowerShell 才能执行）。
- **改名不会改变显示的名字与版本号。** 横幅上的名字 / 版本 / 副标题来自 `ordinary-dsh-launcher.ps1`
  **最上方**（`param` 块之后）的「启动器身份」三行常量；`.cmd` 里不再重复写名字和版本，窗口标题也由
  `.ps1` 用同一份身份设置：

  ```powershell
  $Script:LauncherName    = 'ordinary dsh launcher'
  $Script:LauncherVersion = '0.2.0914'
  $Script:LauncherTagline = 'DeepSeek Harness 快速启动器'
  ```

- 数据目录名固定为 `.dsh-launcher\`，不随文件改名变化（改的是文件名，不是数据目录名）。

### 分享给别人

1. 复制整个 `ordinary-dsh-launcher\` 文件夹；
2. **删掉里面的 `.dsh-launcher\`**（含你的 token、路径与日志）；
3. 对方需要自备 Windows + PowerShell 5.1（或 7）+ Node.js；
4. 对方双击 `.cmd` 即可，默认就在启动器文件夹里干活。

## 运行时数据目录 `.dsh-launcher\`

> **这一节的说明也写在 `ordinary-dsh-launcher.cmd` 里**（就是双击的那个文件）——
> 用记事本打开入口文件就能看到，不必去翻 `.ps1`。`.ps1` 里则是同样的说明加上每个函数的实现注释。

### 它是什么

`.dsh-launcher\` 是**启动器自己的运行时数据目录** —— 不是 dsh 的，也不是你项目的：

- **名字固定**：永远叫 `.dsh-launcher\`，不随两个脚本改名而变化；
- **位置固定**：永远和 `ordinary-dsh-launcher.cmd` 在同一个文件夹里；
- **由启动器自动创建**：不需要你准备，也不该手工往里放东西。

它存在的唯一原因，是启动器要能回答两个 PowerShell 本身回答不了的问题：

1. **「我刚才启动的那个 GUI 现在还在不在？它的地址是什么？」**
   `Start-Process` 返回的进程对象，一旦启动器退出就没了。所以 PID / 端口 / 完整访问地址必须落盘，
   这就是 `state.json` —— `[6]` → `[3]` 查看、`[4]` 停止、`[9]` 查看地址，全部以它为数据来源。
2. **「GUI 起来了没有？起不来是为什么？」**
   `dsh web` 的 stdout / stderr 必须落到文件里，启动器才能一边轮询一边等就绪
   （探测 `dsh web: <url>` 那一行），出问题时也才有现场可看 ——
   这就是 `logs\web-*.out.log` / `.err.log`，也是 `[6]` → `[5]` 显示的内容。

### 为什么「第一次启动 cmd 就出现」

启动器一进主流程就**无条件**调用 `Initialize-DataDir`（`ordinary-dsh-launcher.ps1` 第 1833 行），
它做的第一件事就是建三样东西：

```
.dsh-launcher\             ← 建
.dsh-launcher\logs\        ← 建
.dsh-launcher\.gitignore   ← 建（内容为 * 与 !.gitignore）
```

这一步**发生在你选菜单之前**：哪怕你打开启动器后立刻选 `[0]` 退出，
这三个东西也已经躺在磁盘上了。所以「第一次双击 `.cmd` 就冒出来」是预期行为，不是异常。

### 为什么「源源不断出现新文件」

每启动一次 GUI（`[1]` `[2]` `[3]`）都会用**当前时间戳**新开一对日志
（`web-<yyyyMMdd-HHmmss>.out.log` / `.err.log`）。
旧日志**一律保留 —— 不覆盖、不轮转、不自动清理**，这是有意为之：每次启动的现场都留着，方便事后对账。
代价就是文件越攒越多：不想留，用 `[6]` → `[6]` 清理（见[菜单说明](usage.md#6-子菜单)）。

### 一定会出现的文件

| 路径 | 何时出现 | 作用 | 删掉的后果 |
|---|---|---|---|
| `.gitignore` | 首次运行**立即** | 内容 `*` + `!.gitignore`，让整个目录默认不被 git 追踪，避免 token / 路径被误提交 | 无影响，下次运行自动重建 |
| `logs\` | 首次运行**立即** | 日志目录 | 无影响，下次运行自动重建 |
| `state.json` | **启动成功之后**才写（脚本 747-760 行附近；启动失败不写） | 记录 `pid` / `port` / `url`（含 token）/ `workspace` / `startedAt` / `outLog` / `errLog` / `mode` / `entry` / `appArgs` / `elapsed` | 只丢失「当前运行中的那个 GUI」这条线索：`[6]`→`[3]` 会显示「无运行中的 GUI」、`[9]` 拿不到地址。**GUI 本身照常运行**，但 `[6]`→`[4]` 也停不掉它了，只能手工杀进程 |
| `logs\web-<时间戳>.out.log` | 每启动一次 GUI | `dsh web` 的 stdout（重定向而来）。启动器的就绪探测就是轮询这个文件；`[6]`→`[5]` 显示的也是它 | 无影响。但若删的是**正在运行**那一次的日志，会因文件被进程占用而删不掉（与[安全说明](security.md#仍有残留风险请知悉)第 1 条同源） |
| `logs\web-<时间戳>.err.log` | 每启动一次 GUI，与上一条成对 | `dsh web` 的 stderr。**正常情况是 0 字节**；启动失败时失败原因写在这里，所以排查启动失败别只看 `.out.log` | 同上 |

> `state.json` 不会在 GUI 停止时被立刻删除。下次运行启动器时 `Get-LiveGuiState` 会校验里面的 PID 是否还活着，确认已死才顺手清掉。

### `web-*.out.log` 里到底有什么

它**只是 `dsh web` 的 stdout 重定向文件**，不是 dsh 的运行记录。实测一份真实日志（连续跑了约两小时）的**全部**内容就是这样：

```
   1  dsh web: http://127.0.0.1:3080/?token=…        ← 启动横幅
   2  dsh web: opening the default browser; …        ← 是否自动开浏览器
   3  SharedMemory read faild
   …  （同一行重复，一直到第 285 行）
 285  SharedMemory read faild
```

**2 行有用 + 283 行噪声（占 99%）**，而噪声全是移动云盘 mCloud 的 Shell 扩展写进来的
（怎么进来的见[常见问题](faq.md#常见问题)）。所以：

- **正常运行时这个日志几乎没东西可看** —— 这是正常的，不是启动器坏了。
  它真正有用的时候是**启动失败**：失败原因写在这里，stderr 的原因写在同名 `.err.log` 里。
- 有用内容集中在**文件开头**（启动信息）和**失败时的末尾**，所以
  `[6]` → `[5]` 已经不再只显示「尾部 40 行」（那会 100% 落在噪声里），
  而是先给构成统计、再单独列出「值得看的行」，最后才显示折叠掉重复的尾部。
- **历史对话、工具调用、agent 输出都不在这个文件里**，它们属于会话记录
  （`%DSH_HOME%\sessions\`），别指望用这个日志回放会话。
- ⚠️ 文件**第 1 行的 token 是明文的**：运行中的实例洗不掉（见[安全说明](security.md#仍有残留风险请知悉)第 1 条）。
  `[6]` → `[5]` 显示时会打码，但**文件本身仍然带着它** —— 要把日志发给别人之前，
  先 `[6]` → `[4]` 停掉 GUI 让它自动清洗，或用 `[6]` → `[6]` 清掉。

### 可能出现的文件（**不是**启动器生成的）

下面这些来自外部辅助脚本或历史残留。启动器脚本里**没有任何一行代码**会创建或读写它们（已逐行核对），
出现与否都不影响启动器运行，可以放心删：

| 路径 | 谁写的 | 作用 |
|---|---|---|
| `logs\gui-restart-<时间戳>.log` | GUI 重启助手 | 重启过程记录：预检 → 等待 N 秒 → 停旧 GUI → 等端口释放 → 拉起新实例 → 确认监听 |
| `logs\gui-restart-<时间戳>.launcher-<n>.out.log` / `.err.log` | 同上 | 重启助手把**启动器自己的控制台输出**也重定向下来的副本（含进度条、耗时、掩码后的地址） |
| `logs\gui-restart-<时间戳>.preflight.txt` | 同上 | 动手重启前的环境快照，出问题后用来对账 |
| `restart-gui.ps1` | 手工 / 助手放入 | 「杀掉当前 GUI 再拉起来」的一次性脚本（需要它的原因：bundle 插件只在 `dsh web` 启动时组装进 boot 图，装完必须完整重启） |
| `restart-stdin.txt` | 同上 | 给重启后拉起的启动器喂的空 stdin，避免它卡在交互读取上 |
| `*.bak`（如 `dsh-launcher.ps1.before-npx-fix.bak`） | 手工留档 | 旧版脚本备份，纯留档 |

> **搬运 / 改名提示**：这些残留脚本**不受**本文《可以随处移动吗》的承诺保护 ——
> 它们不是启动器的一部分，内部往往写着**硬编码的绝对路径**（例如把日志写回旧的 `.dsh-launcher\logs`），
> 换了位置后就别再指望它们还能用。

### 一份启动器 = 一份数据目录

数据目录是**跟着启动器文件夹走的**，所以：

- 把启动器复制成两份（两个文件夹），就会有两份**互不相干**的 `.dsh-launcher\`；
- **A 处的启动器看不到 B 处启动的 GUI。** 菜单顶部的「当前状态」、`[6]` → `[3]` / `[4]`、`[9]` 的地址，
  都只看**自己这一份** `state.json`；
- 同理，自检的「日志里是否残留明文 token」也只扫自己这一份 `logs\`。
  另一份启动器留下的日志里有没有明文 token，它无从得知。
- 想管理某个 GUI，就用**当初启动它的那个启动器**去管。

### 分享 / 清理

- 想彻底干净：**直接删掉整个 `.dsh-launcher\`**。下次运行启动器会自动重建，只是丢掉历史日志和「运行中 GUI」的识别。
- `.gitignore` 只挡 `git`，不挡拷贝、压缩包和上传。**分享给别人之前，先删掉 `.dsh-launcher\`。**
