# 设计与性能

本页收录性能设计取舍与各菜单项的耗时显示。

---

## 性能设计

启动慢曾经主要来自启动器自己，而不是 dsh。实测并修掉的两个热点：

| 操作 | 改前 | 改后 | 说明 |
|---|---|---|---|
| 端口探测（20 个端口） | ~900 ms | ~64 ms | 改成一次 `netstat` 建表 + 缓存，不再逐端口调用 `Get-NetTCPConnection` |
| dsh 入口解析 | ~884 ms | ~145 ms | 快路径命中即返回，不再无谓地跑 `npm root -g` |

关键事实：`Get-NetTCPConnection` 在权限不足时会**每次抛异常**，本机单次耗时约 840 ms；
`npm root -g` 约 970 ms；而一次 `netstat -ano` 全表只要约 21 ms。

其他：等待就绪时显示 spinner + 进度条 + 实时秒数，完成后报告总耗时。

> 进度条按 20 秒填满，纯属视觉估计，**不是**剩余时间承诺。

### 耗时显示

凡是「会等」的菜单项都在结束时打一行暗灰耗时（`Format-Duration` / `Write-Elapsed`），
便于区分「慢」和「卡死」，也能看清时间花在哪一步：

| 菜单项 | 显示的计时 |
|---|---|
| `[1]` `[2]` `[3]` 启动 Web UI | 进度条实时秒数；结束报告启动耗时（失败/未拿到 URL 也报告） |
| `[4]` 查看当前安装版本 | 入口解析耗时、`dsh --version` 耗时、本项总耗时 |
| `[5]` 查看最新可用版本 | registry 查询耗时（超时则标注 30 秒上限）、本地入口解析耗时、本项总耗时 |
| `[6]` → `[1]` 环境自检 | dsh 入口解析耗时、自检总耗时 |
| `[6]` → `[2]` 修复 / 重新安装 | 每步耗时（npx 拉取、npm 全局安装、`--version` 复核）+ 合计（**不含**等待输入的时间） |
| `[6]` → `[3]` 查看运行中的 GUI | 本项总耗时（netstat + CIM 查询） |
| `[6]` → `[4]` 停止运行中的 GUI | 停止耗时（含进程收尾与日志清洗） |

看日志、清屏、打开浏览器这类不等待的菜单项**不加**计时，避免噪声。
